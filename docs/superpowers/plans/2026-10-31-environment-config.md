# Build-time environment configuration

Implement the documented `--dart-define-from-file` workflow on the current task
branch. Preserve the existing `.env` workflow for debug development only.

1. Add resolver tests for selecting a complete build-time config, refusing
   partial overrides, validating URLs and public keys, and requiring the known
   production endpoints at release startup.
2. Introduce one immutable app configuration used by Supabase initialization,
   push registration, payment initiation/callbacks, and profile web links.
   Selected build-time values must never inherit values from `.env`.
3. Copy the existing public staging/production JSON files into this worktree;
   leave the primary checkout's local settings and unrelated changes untouched.
4. Update README commands and state the exact limits of the release startup
   validation. Build-time selection requires a full restart/rebuild.
5. Run targeted resolver tests, then `scripts/verify-change` in its required
   analysis/test/emulator order. Inspect its screenshot and verify the staging
   compile-time path on Android as well as the legacy development fallback.

No production database changes, notification sends, signing changes, or store
submission are part of this implementation.

## Verification results

- `scripts/verify-change` passed analysis, 140 tests, and Android build/install/
  launch. The 35 existing informational analysis findings remain. One conditional
  bootstrap test was skipped in this run and passed separately with
  `--dart-define-from-file=test/fixtures/config/production.json`.
- Inspected `build/verification/android-emulator/screenshot.png` and its UI
  hierarchy: onboarding rendered correctly.
- Built with the real staging JSON while the bundled `.env` contained only a
  comment. Confirmed the empty asset inside the APK, restored the local `.env`,
  then cold-launched twice. Both sign-in screenshots under
  `build/verification/environment-config/` were inspected; no fatal runtime
  errors appeared. No production login, payment, or notification was performed.
- Independent review identified the profile/local-HTTP mismatch. Bootstrap now
  follows the push client's debug-only HTTP policy, with a passing regression.
- The existing emulator had a higher installed version and insufficient space.
  Final verification used a clean temporary API 34 emulator, ARM64-only APKs,
  build number 2002, and a 20-second startup window. These verification-only CLI
  settings did not change the source version. Existing emulator user data was
  preserved. Unrelated Apple setup files generated by Flutter were removed from
  the task worktree.
